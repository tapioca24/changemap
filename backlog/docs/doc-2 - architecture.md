# 設計と保守上の判断

利用者向けの現行仕様は [usage](<doc-1 - usage.md>)、開発・検証手順は [CONTRIBUTING.md](../../CONTRIBUTING.md)、用語は [CONTEXT.md](../../CONTEXT.md) を参照する。この文書は、実装を変更する際に維持すべき判断とその理由を記録する。型や内部APIの詳細はソースを正本とする。

## 製品の目的と構成

変更ファイル同士の関係を俯瞰し、ファイルツリーから依存関係を頭の中で組み立てる負担を減らす。特定のレビュー順序を強制しない。ファイル間のモジュール参照を表示し、関数の呼び出しや実行時のデータフローは表現しない。

CLI・HTTPサーバー・React UIを単一のnpmパッケージとして配布する。実装言語はTypeScript。Node.jsを含む単体実行ファイルや複数パッケージへの分割は採用していない。CLIをフォアグラウンドで動かし、ブラウザのタブを閉じてもサーバーは継続する。開発用依存が配布不備を隠さないよう、空のstore/cacheからtarballを隔離導入して検証する。

## Git取得とレビューの固定

[snapshot.ts](../../src/git/snapshot.ts) は差分・全文・解析設定・両状態の依存グラフを一組として生成する。比較の方向、第一親、初回コミット、未追跡ファイルなどの仕様はusageに集約する。

取得前後の参照先、ファイル集合、内容、モードを照合する。更新時刻だけでは同じサイズの編集を取り逃がすため、内容の照合に伴う読み取り負荷を受け入れる。不一致の結果は破棄し、初回を含め最大3回試す。連続読み取りの検証であり、途中で変更して元に戻る場合まで検出できる原子的な取得ではない。

[state.ts](../../src/git/state.ts) はコミットをls-tree・cat-fileで読み、インデックスは空ツリーとの読み取り専用比較から取得する。intent-to-addの空プレースホルダーをステージ済み追加と誤認しない。シンボリックリンクはリンク先文字列を保持し、リンク先を読まない。

[diff.ts](../../src/git/diff.ts) は独立した一時bareリポジトリに固定データをfast-importし、Gitの50%閾値でリネームを判定する。利用者のGit設定・環境変数を引き継がず、比較元のindexやobject databaseへ書き込まない。成否にかかわらず一時リポジトリを削除する。実バイトを比較し、clean/smudge等は適用しない。

先頭8,000バイトにNULがある内容、またはUTF-8でない内容はバイナリとする。テキスト差分が空である場合と、バイナリのため差分を表示できない場合を区別する。

[ReviewSession](../../src/review/session.ts) は生成がすべて成功してからスナップショットを置換する。同時更新はまとめ、検知処理との競合を避ける。Git側とブラウザ側はそれぞれ前回処理終了後1.5秒間隔でHTTPポーリングする。更新検知は通知に留め、明示更新までグラフとコードを維持する。更新失敗時も既存の比較を維持する。

全文取得はスナップショットIDと前後のパスで識別し、要求パスを実ファイルシステムへ渡さない。古いIDへの要求は409にし、異なる比較の内容を混在させない。

画像プレビューはPNG・JPEG・GIF・WebPに限定する。拡張子は信頼せず、実バイトの形式ヘッダーからMIME型と寸法を判定する。1画像10 MiB、各辺8,192 px、合計2,400万画素を超えるもの、symlink・submoduleは配信しない。圧縮後サイズだけでは展開後の負荷を抑えられないため、画素数も制限する。SVGやPDFなど、ブラウザで能動的に扱える形式は対象外とする。アニメーションはブラウザ標準の再生に任せ、フレーム数の上限は設けない。

画像専用APIはHEADで表示可否・MIME型・寸法、GETで実バイトを返す。既存の同一origin・Host・Origin検査とスナップショットID照合を共用し、保存済みスナップショット以外は読まない。MIME型は許可した4種類の固定値、`X-Content-Type-Options: nosniff`、`Cross-Origin-Resource-Policy: same-origin`、`Cache-Control: no-store`を付与する。画像の破損などブラウザでのデコード失敗はUIに理由を示す。サーバー側で画像を再エンコードしないため、ブラウザの画像デコーダに残るリスクはある。形式と画素数の制限は[OWASP ASVS](https://cornucopia.owasp.org/taxonomy/asvs-5.0/05-file-handling/02-file-upload-and-content)を参考にした。MIME型と`nosniff`の意味は[MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options)を参照する。

## 固定データ内の依存解析

[仮想ファイルシステム](../../src/analysis/filesystem.ts) は固定データだけを仮想 /snapshot 以下へ公開し、大文字小文字を区別する。作業ツリー、インストール済み依存、外部設定、TypeScriptの標準libへのfallbackを持たせない。バイナリ・symlinkはソースとして解釈しない。

[TypeScript Compiler API](../../src/analysis/typescript.ts) を実行時依存のtypescript-api aliasで使用する。型チェック用TypeScriptとは分ける。ts-morphは方式比較の開発依存に留める。[解析方式の比較と測定](<doc-3 - analysis-performance.md>)に、構文走査では定数経由の参照を落とすこと、ts-morph Projectでは測定時のRSS目標を超えたことを記録する。

直接の利用元を検出するため、全対象ファイルの参照を走査する。表示範囲だけを先に解析すると利用元を取り逃がす。長い環状依存鎖での再帰読み込みによるスタック上限を避け、全対象ファイルをrootに渡してnoResolveを有効にする。依存先の解決はresolver、式の型情報はcheckerを使い、独自の式評価は追加しない。

設定ごとにProgramを構築するため、設定数が多い場合には時間・メモリが増える。[config.ts](../../src/analysis/config.ts) が設定の所属を選び、固定したCompiler APIのmatchFilesに型アダプターを設けてglobを扱う。対応構文、設定選択、外部除外と未解決の境界はusageを参照する。

未解決参照と設定・構文診断は全体の不完全通知へ集約する。表示範囲外の未解決参照も利用元の欠落を起こし得る。仮の依存先ノードや辺は追加せず、意図的な外部除外と区別して記録する。

## 前後の統合と表示範囲

[merge.ts](../../src/graph/merge.ts) はGitがrenameと判定した旧・新パスだけを同一ファイルに対応付ける。内容や依存関係から独自にrenameを推測しない。辺の両端を同一性で正規化してから追加・削除・不変を判定する。BをB′へrenameし、Aのimportを追従させた場合、A→Bの依存は不変とし、ファイルの変更表示は残す。

ノードIDは比較内でのみ有効。前状態のパスを基準とし、追加ファイルには後状態の名前空間を使う。旧パスを新規ファイルが再利用しても衝突しない。片側だけ解析対象のrenameも一つのノードにまとめ、解析されている側の辺を保持する。

全変更ファイルと、変更前後の直接の依存先・利用元の和集合を選ぶ。選択されたノード間の辺は両状態からすべて残す。離れた変更同士の経路を自動補完せず、ファイルノードや依存辺は集約しない。例えば変更A→未変更B→未変更C→変更DではB→Cも表示するが、変更A→未変更B→未変更C→未変更D→変更Eでは他の接続がなければCは選ばれない。

この表示方針はDelta TypeScript Graph Actionのコード読解を参考にした。調査対象はActionのcommit ca315569e76ea289de14d72acce2e86152b92aceとtypescript-graph v0.26.5で、実行検証ではない。[周辺選択と辺の復元](https://github.com/ysk8hori/typescript-graph/blob/v0.26.5/src/feature/graph/filterGraph.ts)と[統合・集約](https://github.com/ysk8hori/delta-typescript-graph-action/blob/ca315569e76ea289de14d72acce2e86152b92ace/src/graph/mergeGraphsWithDifferences.ts)を参照した。changemapではファイル単位の依存辺を維持し、ディレクトリは表示上の入れ子枠とする。同Actionの辺の集約やノード上限による非表示は採用していない。

## UIと設定の判断

React FlowとDagreを使用する。初版の平坦なファイル配置に対してDagreを採用し、現在は表示対象ファイルのディレクトリ階層を入れ子枠として配置する。各階層で直下のファイルと子ディレクトリをDagreに渡し、階層をまたぐ依存は代表ノード間の辺として配置に反映する。ファイル間の依存辺は集約せず、配置後の端点を固定した三次Bezier曲線で描画する。逆向きの辺はDagreの経路を参考に外側へ迂回させる。同じ接続点に集まる辺の制御点は扇状にずらす。ファイル選択時、またはエッジやファイルのホバー時には関連する辺を強調し、同色の円を依存方向へ流す。ホバー中はその対象を優先する。円は両端でフェードし、動きを減らす設定では隠して線の強調だけを残す。線幅はコード内の定数で管理する。リネームは新パス、削除は旧パスのディレクトリに置く。[layout.ts](../../src/ui/layout.ts) と [graph.tsx](../../src/ui/graph.tsx) を参照する。

配置は同期処理で、中断機能はない。例外時はファイル選択から固定コードを読める状態を残すが、グラフ描画成功とは扱わない。[描画測定](<doc-4 - rendering-performance.md>)に10,000ノードでの失敗と測定範囲を記録する。

ノードの選択やテーマ変更でグラフ全体を再描画しないようmemo化し、未解決参照は状態別Setで索引化する。更新成功時は選択を解除する。全文の遅延応答は現在の選択とスナップショットに一致した場合だけ反映する。コード表示は差分色と行番号を提供し、言語別の構文ハイライトは提供していない。

設定は個人の全プロジェクトで共有するTOML。テーマと方向をUI変更時に保存し、起動だけでは作成しない。プロジェクト別上書きやCLIによるテーマ・方向指定は設けていない。設定の保存先・スキーマはusageを参照する。

[settings.ts](../../src/config/settings.ts) は同一サーバー内で保存を直列化し、一時ファイルを書いてrenameする。未知キーを残すが、コメントと書式は保持しない。破損設定で起動した場合は起動中の保存を禁止する。保存前にも再読込し、起動後に破損したファイルを上書きしない。保存に失敗しても画面の設定は維持し、永続化されなかったことを通知する。

[server.ts](../../src/server/server.ts) は127.0.0.1で待ち受け、Host・Originと静的配信パスを検証する。変更APIはカスタムヘッダーを要求する。React Flowの位置指定に必要なinline styleをCSPで許可し、スクリプトと通信は同一originに限定する。
