# changemap 設計メモ

設計ヒアリング中。確定した要望と未確定の提案を区別し、回答に応じて更新する。実装計画とBacklog.mdのタスクは、設計を詰めてから作成する。

## 目的

変更に関係するファイル同士の依存関係を俯瞰しやすくする。ファイルツリーから関係性を頭の中で組み立て直す負担を減らす。

末端から読むのは利用者の選択肢の一つであり、特定のレビュー順序を推奨・強制することを製品の中心に置かない。

## 確定している要望

- CLIを実行するとローカルサーバーが起動し、ブラウザで開く。
- 変更に関連する依存関係をグラフで表示する。
- ファイルのノードを選択すると、右側のペインにコードを表示する。
- テーマを切り替えられる。Catppuccinを好み、グラフ・コード表示・UI全体に適用したい。
- ノードの追加・変更・削除を、それぞれ緑・黄・赤で区別する。
- 最初の対象言語はTypeScript。将来はGoにも対応したい。
- npmでの公開名は `changemap` を希望する。名称の利用可否は未確認。
- プロジェクト管理にはBacklog.mdを使う。
- パッケージマネージャーはpnpmを使う。
- READMEは英語のみとする。
- CLIの基本モードはDifitのインターフェースを踏襲する。引数なしはHEADの最新コミット、`<target>` は単一コミット・ブランチ、`<target> [compare-with]` は二つのコミット・ブランチの比較とする。`.` はステージ済みと未ステージを含む未コミット変更、`staged` はステージ済み変更、`working` は未ステージ変更を表す。`@` はHEADの別名として扱う。
- GitHub PR（`--pr`）とGitLab MR（`--mr`）への対応は初版には含めない。将来追加する際に、差分取得方法、認証、既存コメント連携を改めて設計する。
- 比較対象はコミット・ブランチ間と未コミット変更の両方に対応する。
- CLIの引数や比較対象の指定はDifitのインターフェースを踏襲する。個々のオプションの対応範囲は未確定。

## 技術候補

TypeScript、React、ts-morph、React Flowがユーザーの初期案。現時点では採用決定ではない。

## 変更前後の表現

変更前後の依存関係を一つのグラフに重ねて表示する。ノードの変更状態はファイルの追加・変更・削除を示し、線の変更状態は依存関係の追加・削除を示す。削除されたファイルと依存関係も表示対象に残す。削除ファイルを選択すると削除前のコードを表示する。ユーザー承認済み。

別々の図を見比べる負担を減らす一方、線が増えて混雑しやすくなる点を受け入れる。具体的な線の色・線種は未確定。

Gitがリネームと判定したファイルは、変更前後を一つのノードにまとめる。ノードは変更と同じ黄色にし、「移動・リネーム」のラベルを付け、旧パスと新パスを確認できるようにする。変更前の依存関係もそのノードに接続し、右ペインで移動に伴うコードの差分を確認できる。ユーザー承認済み。

追加・変更・削除の状態は色だけでなく、ラベルまたはアイコンでも示す。テーマ変更や色覚特性によって色の意味が失われないようにする。ユーザー承認済み。具体的な記号と配置は未確定。

## 依存関係の定義

初版の依存関係は、ファイル間のimportおよび再エクスポートとする。型だけの参照も含める。同じ向きの同じファイル間の参照は一本の線にまとめ、矢印は参照元から参照先へ向ける。関数の呼び出し関係や実行時のデータの流れは表現しない。ユーザー承認済み。

動的import、CommonJSのrequire、外部パッケージ、解決できない参照の扱いは未確定。

## テーマ

初版はCatppuccinのLatte・Frappé・Macchiato・Mochaを同梱する。テーマを切り替えるとグラフ・コード表示・UI全体を一括で変更する。追加・変更・削除には各テーマの緑・黄・赤を使い、色の意味を統一する。ユーザー承認済み。

初期テーマはMochaとする。ユーザーがUIから選択したテーマは共通設定へ保存し、次回起動時に読み込む。

グラフとコードに別々のテーマを指定する機能は、現時点の検討対象から外す。独自テーマの読み込みは初版に含めず、将来の拡張候補にとどめる。初期テーマと選択の保存方法は未確定。

## グラフレイアウト

デフォルトの向きは、依存元から依存先へ左から右へ並べるLRとする。向きは初版から設定で変更できる。設定可能な値と設定方法は未確定。

## 設定の保存

プロジェクト内に `changemap.config.*` を置いてチーム共有する形ではなく、個人がグローバルインストールして使うCLIを前提とする。UI上で変更した設定は、XDG Base Directory Specificationに準拠した個人用設定ファイル（例: `~/.config/changemap/config.toml`）へ保存し、次回起動から反映する。ユーザー承認済み。

設定は全プロジェクト共通とし、初版ではプロジェクトごとの上書きを持たせない。CLI引数との優先順位、設定ファイルの自動生成・破損時の扱いは未確定。

## コード表示

変更ファイルを選択すると、右ペインには差分を標準表示し、必要に応じて全文へ切り替えられる。未変更の関連ファイルでは全文を、削除ファイルでは削除前の内容を表示する。ユーザー承認済み。

TypeScript以外の変更ファイル（package.json、CSS、設定ファイルなど）も変更一覧に載せ、右ペインで差分を閲覧できるようにする。初版の依存関係解析はTypeScriptに限定する。解析対象外の変更ファイルは「依存解析の対象外」と分かる区画に、線のないノードとして表示する。「依存関係がない」と「解析していない」を区別し、ノードを選択すると差分を開ける。ユーザー承認済み。

## レビュー機能の範囲

初版は差分閲覧に絞り、行へのコメントと、コメントをAIへ渡すためのコピー機能は含めない。初版のスコープを小さく保つための判断であり、両機能はユーザーの強い要望として初版後の優先度の高い拡張候補に残す。ユーザー承認済み。実装時期は未確定。

## 更新検知

未コミット変更のレビュー中に作業ツリーの更新を検知した場合、表示中のグラフとコードを自動で差し替えず、更新があることと更新ボタンを表示する。ユーザーが明示的に更新した時点で、比較結果・依存関係・表示をまとめて読み直す。レビュー中の表示を安定させるための要件として、ユーザー承認済み。

初版の検知方法は、ローカルサーバーが一定間隔でGitの状態を確認し、ブラウザへ更新通知を送る方式とする。ファイル監視は将来の改善候補。検知対象とする変更（作業ツリー、インデックス、参照先コミット）の範囲はCLIの比較モードと合わせて決める。ユーザー承認済み。

## 表示範囲の検討

初期表示は「すべての変更ファイル＋直接の依存先・利用元」とする。表示対象のファイル同士を結ぶ依存関係の線もすべて残す。離れた変更ファイル同士をつなぐために、経路上の未変更ファイルをすべて自動補完することはしない。Delta TypeScript Graph Actionの調査を踏まえ、ユーザーが承認済み。

表示単位はファイルとする。初版では未変更ファイルをディレクトリノードに自動集約しない。将来的に、集約を含む表示の振る舞いをユーザー設定で調整できるようにする案は拡張候補であり、初版の要件には含めない。

初版では、ノード操作によって関連ファイルをさらに追加表示する機能は提供しない。変更とその直接の周辺の把握を重視し、それを超える広範なコード探索はIDEなどの責任範囲と考える。ユーザー承認済み。

依存関係を事前にすべて取得する方式は採用決定ではない。大規模プロジェクトでの解析時間が懸念されるため、一括解析・索引・必要時の解析などの内部方式は、設計検討時に試作・計測して決める。表示範囲の要件と解析方式を分け、利用元の検出に必要な走査範囲も検証する。

### Delta TypeScript Graph Actionの調査

GitHub API経由でActionのmain（`ca315569e76ea289de14d72acce2e86152b92ace`）と、依存先 `@ysk8hori/typescript-graph` の指定バージョン `0.26.5` のソースを確認した。以下はコード読解による結果であり、実行検証ではない。

- 変更ファイル（リネームでは旧・新パス）を中心に、直接の依存先と利用元を抽出する。全方向に再帰的に辿る処理ではない。
- 抽出された周辺ノード同士の既存の線も復元する。`変更A → 未変更B → 未変更C → 変更D` ならBとCがそれぞれ変更ファイルの隣接ノードなので、B→Cも表示対象になる。先の会話でこの例を途中で切れると説明したのは不正確だった。
- `変更A → 未変更B → 未変更C → 未変更D → 変更E` では、他に接続がなければ中央のCは選ばれず、経路全体は表示されない。
- フィルタリング後、変更ファイルを含むディレクトリとその祖先を保護し、それ以外のディレクトリの表示対象ノードをディレクトリノードに集約する。同じ保護ディレクトリ内の未変更ファイルは個別に残り得る。
- `node_modules` はデフォルトで除外する。
- `include-index-file-dependencies` はデフォルトfalse。有効時は、変更ファイルを参照する同階層の `index.ts` / `index.tsx` を中心の集合に追加し、その周辺も拾う。一般的な任意深度の再エクスポート追跡ではない。
- `max-size` はデフォルト30。集約後のノード数が上限を超えるとグラフを表示しない。上限まで一部を表示する仕様ではない。
- 通常は変更前後を統合する。削除や対象リネームがある場合は変更前後を別の図で表示する。
- 実装上の注意：依存ライブラリのinclude判定は大文字小文字を無視したパス部分一致であり、厳密なパス一致による1ホップ選択とは異なる場合がある。changemapへの採用判断は、この細部と基本方針を分ける。
