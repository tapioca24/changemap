## 実装範囲

Git入力の解決、変更前後の固定データ、差分と全文の取得、ローカルHTTPサーバー、Reactアプリの起動、更新検知と明示的な再取得を実装する。依存解析・グラフ・本格的なコードペイン・設定保存は後続フェーズの対象とする。

既に合意済みの比較方向、第一親、初回コミット、未追跡ファイル、モード別の通知条件は再確認せず踏襲する。Gitのインデックスや作業ツリーを変更しない。

## 合意した取得方式

取得中の変更を検証する方式と再試行上限はroadmapで実装前の決定を求められている。

コミット指定は解決済みのオブジェクトから読み、可変な参照・インデックス・対象作業ツリーについて取得前後の参照先、ファイル集合、内容、モードを照合する。ファイルの更新時刻だけには依存しない。不一致の取得結果を破棄し、初回を含め最大3回試す。上限に達したら原因を返し、既存の固定データを維持する。ユーザー承認済み。

内容の照合は読み取り負荷が増えるが、同じサイズの編集や更新時刻だけでは判別できない変更を検知できる。ファイルシステム全体の原子的な取得を保証する方式ではなく、照合の間に変更して元に戻るケースなどの限界は明記する。ポーリングでも比較に関係する状態だけを照合する。

5. ローカルサーバー、ブラウザ起動と起動抑制、終了処理、Reactの最小画面を実装する。通信・ポート・UIビルドの具体案は実装時の調査を踏まえて記録する。

- モード別の通知条件と参照の再解決が仕様どおりに働き、自動では固定データを置換しない。

## 実装した構成

- `src/git/`：入力解決、コミット・論理インデックス・作業ツリーの読み取り、固定データ、差分生成。コミットの第一親はコミットオブジェクトから読み、shallow境界を初回コミットと取り違えない。
- `src/shared/review.ts`：変更状態、比較対象、固定ファイル、HTTP応答の型。設定専用の可変読み取りは設けず、各状態の全リポジトリファイルを保持する。フェーズ2の解析はこの固定データを入力にする。
- `src/review/session.ts`：取得成功時だけデータを置換する。ポーリングと更新を競合させず、同時の更新要求をまとめる。
- `src/server/server.ts`：Node.js標準HTTP。`127.0.0.1`だけで待ち受け、既定ポート0で空きポートを選ぶ。`--port`で明示指定でき、使用中ならエラー。Host・Origin検証、静的配信のパス制限、更新用カスタムヘッダーを実装。
- `src/cli/`：ブラウザを既定で起動。`--no-open`で抑制でき、起動失敗でもURLとサーバーを維持する。SIGINT/SIGTERMでHTTP・ポーリング・進行中の処理を終了する。
- `src/ui/`：Reactの比較対象・変更ファイル・展開式差分・バイナリ表示・空状態・更新通知・再試行。依存グラフや本格的なコードペインは追加していない。
- UIビルドはVite、CLIビルドは既存のtsdown。Reactはブラウザ用成果物に同梱するため開発依存として導入し、配布時の追加依存は不要。Viteのライセンス一覧もtarballに同梱する。

ポーリングはGit側・ブラウザ側とも前回処理完了後1.5秒間隔。通知通信はHTTPの状態取得とし、SSE/WebSocket用の持続接続は設けない。Git更新検知とブラウザの再取得は独立し、通知で比較結果を差し替えない。

### 固定データと差分

`ls-tree`・`cat-file --batch`でコミットを読み、インデックスは空ツリーとの読み取り専用比較から取得する。これによりintent-to-addの空プレースホルダーをステージ済み追加と誤認しない。作業ツリーは追跡ファイルと無視対象外の未追跡ファイルを列挙して読み、シンボリックリンクはリンク先の文字列として保持する。

差分は独立した一時bareリポジトリへ`fast-import`してGitに計算させる。リネーム閾値はGitの50%。一時リポジトリでは利用者のGit環境変数やグローバル設定を引き継がず、元リポジトリのindex・object databaseへ書き込まない。成功・失敗のいずれでも一時リポジトリを削除する。

NULを含む先頭8000バイト、またはUTF-8でない内容はバイナリとして保存する。全文はUTF-8文字列かbase64。テキスト差分なしの空文字列と、バイナリのため取得不可のnullを区別する。変更一覧と、未変更を含むレコードの両方を保持する。

### HTTP API

| API                                                      | 内容                                                                                      |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `GET /api/snapshot`                                      | 現在の比較対象、スナップショットID、変更一覧と固定済み差分                                |
| `GET /api/status`                                        | 現在のID、更新通知、取得中フラグ、エラー                                                  |
| `GET /api/file?side=before\|after&path=...&snapshot=...` | 固定済み全文。ID不一致は409、存在しないパスは404                                          |
| `POST /api/refresh`                                      | 全体の取得に成功した場合だけ置換。失敗は503で既存IDを維持。`X-Changemap-Request: 1`が必要 |

全文APIはリクエストされたパスをファイルシステムへ渡さず、固定データだけを参照する。更新後に古いIDで全文を要求した場合、新しい内容を混在させずエラーにする。

## 境界と後続課題

- 全リポジトリファイルをメモリへ取得する。大規模リポジトリの計測と改善はフェーズ2で解析方式と合わせて扱う。
- 作業ツリーは実バイトを比較する。clean/smudge・textconv・属性によるdiff driver・改行の自動変換は適用しない。
- 競合インデックスと作業ツリーモードのsparse checkoutは明示的にエラーとする。欠落オブジェクトの自動fetchは無効にし、利用者に事前取得を委ねる。
- サブモジュールはgitlinkのみ。初期化済みサブモジュールに未コミット内容がある場合は、見落としを避けるため作業ツリーの取得をエラーにする。非UTF-8パスもエラーとする。
- 連続する読み取りの整合性検証であり、途中で変更して元に戻った内容の完全な検出は保証しない。
- 新しい製品用語は追加していない。今回は変更可能な実装上の選択であり、用語集・ADRの追加は行わない。
