# フェーズ3：グラフ差分

## 実装計画

- [x] Gitの変更情報で前後のファイル同一性を対応付け、ノードと辺の状態を判定する。
- [x] 統合後の同一性で直接近傍を抽出し、既存snapshot APIへ追加する。
- [x] リネーム、パス再利用、解析対象の境界、初回コミット、更新を検証する。
- [x] 全チェックと配布検証を実施し、引き継ぎを更新する。

## モデル

既存の before / after / selection を維持し、graph.merged に表示用の統合近傍を追加する。ノードIDは比較内でのみ有効であり、前状態のパスを基準にする。追加ファイルは後状態の名前空間を使い、旧パスの再利用と衝突させない。辺の両端はこのIDを参照する。旧・新パスと解析対象かどうかは状態別に保持する。変更ノードは FileChange を保持し、差分・バイナリ情報にアクセスできる。

Gitがrenameとした対応のみを使う。内容や依存関係から追加のrename推定はしない。変更状態と辺の状態は独立に判定する。片側だけ解析対象のrenameも一つのノードとし、解析されている側の辺を保持する。

## 検証結果

macOS / Node.js 24.14.1で全71テスト、型チェック、lint、整形チェック、ビルドが成功。空のstore/cacheから導入する隔離配布検証で、統合グラフの取得と明示更新を確認した。CI・Linux・Windowsは今回未実行。

初回のテストはノード数の期待値誤り1件とsandboxの待受制限9件で失敗。期待値を正しい3ノードに修正し権限付きで再実行した。その際、並行した配布ビルドによるdistの再生成と競合して1件失敗したため、全テストを単独実行し全件成功を確認した。

グラフ表示、コードペイン、テーマ、設定保存はフェーズ4。表示側では graph.merged のIDで辺を結び、oldPath / newPath とsnapshot IDを使って固定全文を取得する。IDは更新をまたいだ同一性を保証しない。
